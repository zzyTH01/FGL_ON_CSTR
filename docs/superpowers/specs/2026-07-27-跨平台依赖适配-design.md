# 跨平台依赖适配设计

- 日期: 2026-07-27
- 状态: 设计已与用户确认,待 spec 复核
- 分支: feat/adaptive-distill-mse-gap-E
- 落地方案: 方案 2(最小改动 + device 诊断增强)

## 1. 背景与问题

诉求是让本仓库能在"其他电脑"上直接装上并跑起来。排查后把"特殊依赖"分两层看:

- **代码层(`fgl_common/`)已经是跨平台的** ——
  - device 选择 (`fgl_common/training.py:30-36`) 已是 `CUDA > MPS > CPU` 自动检测;
  - `fgl_common/data.py` 的 DataLoader 没有 `pin_memory` / `num_workers`(常见跨平台坑),纯 tuple/tensor;
  - 绘图统一用 `matplotlib.use("Agg")`(无 GUI 后端);
  - 全仓库**没有** `.cuda()` 硬编码、没有 `torch.cuda.manual_seed`、没有 `GradScaler/autocast`;`.to(device)` 全部走统一 `device` 变量。
- **真正的障碍在依赖声明** ——
  - `requirements.txt:3` 把 torch 钉成 `torch==2.1.1+cu121`。`+cu121` 是 CUDA 12.1 / Linux 专用 wheel 标签,`pip install -r requirements.txt` 在 Mac(MPS/CPU)、CPU-only 机器、CUDA≠12.1 的 N 卡机器上会因找不到匹配 wheel 而**安装失败**。
  - `pyproject.toml` 反而是干净的 `torch==2.1.1`,两文件不一致;且 `description` 仍写着早已移除的 "Epilepsy Seizure Detection"。
  - `uv.lock` 连带锁了一堆 `nvidia-*-cu12` 大包,但 marker 限 `platform_machine=='x86_64' and sys_platform=='linux'`,Mac/CPU 机 `uv sync` 会自动跳过 —— lock 文件本身比 requirements.txt 更跨平台。

## 2. 目标

让代码在 **Mac(Apple Silicon/Intel, MPS/CPU)、Linux NVIDIA CUDA、CPU-only 服务器**上都能 `pip install` / `uv sync` 装上并跑起来,且**不损失现有 GPU 能力、不改变任何实验数值**(科研复现性 100% 保留)。

## 3. 设计

### 3.1 依赖声明:去掉平台锁定的 `+cu121`

**`requirements.txt`**
```
- torch==2.1.1+cu121
+ torch==2.1.1
```

**`pyproject.toml`** —— torch 本就是干净的 `==2.1.1`,不动;只修过时描述:
```
- description = "Future Guided Learning for Time Series Prediction (Epilepsy Seizure Detection)"
+ description = "Future-Guided Learning for time-series forecasting (Mackey-Glass / CSTR / Lorenz)"
```

**`uv.lock`** —— 运行 `uv lock` 重新解析,确认一致(torch 仍 2.1.1;`nvidia-*-cu12` 的 `platform_machine=='x86_64' and sys_platform=='linux'` marker 保留,Mac/CPU 机自动跳过)。

> PyPI 上 `torch==2.1.1` 的默认 wheel 三平台齐全:Linux 默认 wheel 自带 CUDA 12.1 支持(连带 nvidia 依赖)、Mac 默认 wheel 带 MPS、CPU 机器装 CPU 默认 wheel。所以去掉后缀**不损失任何 GPU 能力**。

### 3.2 device 选择增强(`fgl_common/training.py:30-36`)

把模块级的三分支赋值,重构成带环境变量覆盖 + 可用性校验 + 启动诊断打印的函数:

```python
import os

def _select_device() -> torch.device:
    """CUDA > MPS > CPU 自动检测。

    可用环境变量 ``FGL_DEVICE`` 强制覆盖(cpu / mps / cuda),用于在 MPS 上
    遇到不支持的 op 时回退 CPU 等场景;指定不可用的设备会显式报错而非静默回退。
    """
    env = os.environ.get("FGL_DEVICE", "").strip().lower()
    if env:
        if env not in ("cpu", "mps", "cuda"):
            raise ValueError(f"FGL_DEVICE={env!r} 不合法,应为 cpu / mps / cuda 之一")
        if env == "cuda" and not torch.cuda.is_available():
            raise RuntimeError("FGL_DEVICE=cuda 但未检测到可用 CUDA")
        if env == "mps" and not torch.backends.mps.is_available():
            raise RuntimeError("FGL_DEVICE=mps 但未检测到可用 MPS")
        return torch.device(env)
    if torch.cuda.is_available():
        return torch.device("cuda")
    if torch.backends.mps.is_available():
        return torch.device("mps")
    return torch.device("cpu")


device = _select_device()
print(f"[fgl] device = {device}")  # 换机器运行时一眼看到落到了哪
```

> 其余约 80 处 `.to(device)` 全部走这个统一 `device` 变量,**无需改动**。
> `import os` 在文件顶部已有的标准库 import 区加入。

### 3.3 README 跨平台说明

在 README 安装段落后新增一小节"在其他电脑上运行",要点:
- 默认自动检测设备(CUDA > MPS > CPU);
- 强制 CPU:`FGL_DEVICE=cpu python cstr/run.py`(应对 MPS 上个别不支持的 op);
- CUDA 机器上 torch 默认 wheel 自带 CUDA,无需额外配置 / 无需 `+cu121` 源;
- 依赖安装命令:`pip install -r requirements.txt` 或 `uv sync`。

### 3.4 验证

1. `python -c "from fgl_common.training import device"` → 本机打印 `[fgl] device = mps`(或 cpu)。
2. `FGL_DEVICE=cpu python -c "from fgl_common.training import device"` → 打印 `cpu`,证明覆盖生效。
3. `FGL_DEVICE=cuda python -c "from fgl_common.training import device"`(本机无 CUDA)→ 抛出清晰 RuntimeError,证明可用性校验生效。
4. `uv lock` 成功且 uv.lock 无冲突。
5. 最小冒烟:跑一个轻量实验(如 `python cstr/run.py -e baseline`,或更小的冒烟脚本)确认不崩。

## 4. 不改动的范围(零数值风险)

- 所有 `.to(device)` 调用;
- DataLoader 配置(无 `pin_memory` / `num_workers`);
- `matplotlib.use("Agg")`;
- `archive/` 里的旧脚本(归档,仅保留可追溯性);
- 实验数值超参、随机种子、模型结构。

## 5. 风险

- **低**。`torch==2.1.1` 默认 wheel 三平台齐全,去掉 `+cu121` 不损失 GPU。
- device 增强是纯增量:未设置 `FGL_DEVICE` 时,选择逻辑与原来逐字等价(同一检测顺序、同一回退),不影响默认行为与数值。
- 唯一可见的行为变化:`fgl_common.training` 模块加载时多打印一行 `[fgl] device = ...`,作为换机诊断。
