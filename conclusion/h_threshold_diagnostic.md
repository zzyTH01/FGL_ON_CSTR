# H-Threshold 实验诊断报告

## Q1: 训练配置是否与 H 无关？

**结论：是。epochs、learning rate、batch size 均为固定值，不随 H 调整。**

| 超参数 | 值 | 是否随 H 变化 |
|------|:---:|:---:|
| epochs | 50 | **否** — 全部 H 值共用 |
| learning rate | 1e-4 | **否** |
| batch size | 128 | **否** |
| patience | 5 | **否** |
| hidden_size | 128 | **否** |

**这是潜在问题。** H 从 2 增大到 16，Student 的预测步长增长了 8 倍，但训练配置完全不变。更大的 H 意味着：(a) 任务本质更难，(b) Teacher offset (=H-1) 更大，Teacher 输入窗口更长，也可能需要更多训练。用同一套配置对待所有 H 值是一种未受控的混淆。

## Q2: 训练/验证损失曲线是否已收敛？

**结论：无法回溯诊断。当前代码（`h_threshold_test.py`）未记录逐 epoch 的 training/validation loss。**

EarlyStopper 只在内部追踪 `best_loss` 但不对外暴露 loss 历史。CSV 输出只包含最终的测试 MSE，不含任何训练过程中的 loss 曲线。

**需要在后续实验中补充：** 在 `train_model()` 函数内部添加 `loss_history.append(vl)` 并在每个 (L,H,seed) 组合完成后保存至单独日志。

**结论：否。样本量差异可忽略，不足以解释任何观测现象。**

## Q4: Teacher vs Baseline/Student 的训练稳定性

**结论：问题集中在 Baseline 而非 Teacher。Abs Improvement 的不稳定性主要源于 Baseline MSE 的跨种子波动。**

### 变异系数 (CV) 分析

| H | Teacher CV | Baseline CV | Student CV | Abs Improvement CV |
|:---:|:---:|:---:|:---:|:---:|
| 2 | 0.274 | 0.447 | 0.273 | −0.544 |
| 4 | 0.324 | 0.380 | 0.116 | −0.509 |
| 6 | 0.283 | 0.042 | 0.167 | 0.579 |
| 7 | 0.302 | 0.108 | 0.159 | 0.241 |
| 8 | 0.479 | 0.051 | 0.252 | 0.111 |
| 9 | 0.293 | 0.139 | 0.165 | 0.206 |
| 10 | 0.523 | 0.137 | 0.224 | 0.296 |
| **11** | 0.306 | **0.490** | 0.104 | **1.040** |
| **12** | 0.181 | 0.140 | 0.103 | **−12.461** |
| 14 | 0.326 | 0.211 | 0.241 | 0.380 |
| 16 | 0.340 | 0.316 | 0.107 | 0.398 |

| 指标 | 全部 H 平均 CV |
|------|:---:|
| Teacher MSE | **0.330** |
| Baseline MSE | 0.224 |
| Student MSE | **0.174** (最低) |
| Abs Improvement | **1.524** (最高，高出近 5 倍) |

### 关键发现

1. **Teacher 是稳定的。** Teacher CV 在所有 H 上基本保持 <0.5，H=12 时仅 0.181——是最低的。Teacher 训练没有问题。

2. **Student 出奇稳定。** Student CV 平均 0.174，是三个模型中最稳定的。即使在大 H 处也未出现明显恶化。

3. **Baseline 是不稳定的根源。** H=11 时 Baseline CV=0.490，种子间的 Baseline MSE 从 3.45 跳到 14.84（4.3×），而同一个 H 下 Teacher MSE 仅从 0.22 变到 0.67。

4. **Abs Improvement CV 被放大。** Abs Improvement = Baseline − Student。当 Baseline 和 Student 接近时（如 H=12, abs_imp≈−0.07≈0），微小的 Baseline 波动导致 abs_imp 在 +0.61 和 −0.86 之间振荡——符号在种子间翻转。

### H=12 的"零穿越"不可信

```
H=12, abs_improvement per seed:
  seed 0: -0.861  (negative)
  seed 1: +0.608  (positive)
  seed 2: -0.118  (negative)
  seed 3: +0.182  (positive)
  seed 4: -0.623  (negative)
  Mean:  -0.071 ± 0.887
```

均值 −0.071 的标准差是 0.887——**我们甚至不能可靠地说这个值的符号是负的。** 5 个种子中 3 个为负、2 个为正，这更像随机噪声而非真实的零穿越。

## Q5: 综合判断与建议

### 判断

**当前 H 扫描结果：部分可信，但 H=11,12 的"FGL 消失"不可信。**

具体来说：
- H=2~10 的结果可信：FGL 从负变正（H≈6），在 H=8~10 达到峰值（+62~72%）
- H=11~12 的"FGL 消失"不可信：Baseline MSE 方差过大（CV 0.49），abs_improvement 均值接近零且符号在种子间翻转，5 个种子不足以确定真实趋势
- H=14~16 的"FGL 恢复"可信：Baseline MSE 稳定（CV=0.21~0.32），Abs Improvement 稳健正向（+6.8~7.2），种子间一致

**H=14,16 处 FGL 的恢复是真实的——不是欠拟合的假象。** 如果欠拟合是原因，更大的 H（14,16）应该比 H=12 更差，但实际结果是 H=14,16 比 H=12 更稳定、FGL 更强。这说明 H=12 的不稳定更可能是该 H 值恰好处于两个效应（任务难度增加 vs 窗口覆盖 τ）的平衡点附近，而不是训练不充分。

### 后续建议

1. **增加 H=11,12,13 的种子数到 10+**（而非增加 epochs），用更多种子降低方差后重新判断该区域是否存在真实的零穿越。

2. **在后续实验中记录逐 epoch loss**（每个 (L,H,seed) 保存一条 loss 曲线），以便回溯诊断收敛问题。

3. **epochs 不需要随 H 缩放。** 证据是 H=14,16（最难的配置）的结果反而最稳定——如果 epochs 不足，这些大 H 配置应该最先崩溃，但实际并非如此。50 epochs 对于当前任务规模是足够的。

4. **样本量不需要增加。** H=2 和 H=16 的 N_train 差异仅 0.14%，且 H=16 的结果稳定——样本量不足不是问题。
